# SMS to Email Forwarder

面向自有设备的短信转邮箱项目。正式工作区归属 `Projects/Server`，采用 GitHub Flow 开发。

## 平台支持边界

| 平台 | 自动读取新短信 | 客户端形态 | 状态 |
| --- | --- | --- | --- |
| Android 8.0 及以上 | 支持 | APK | 开发中 |
| HarmonyOS 2/3/4 Android 兼容环境 | 支持 | 与 Android 共用 APK | Mate 50 Pro / HarmonyOS 4.2 为首个验证目标 |
| HarmonyOS NEXT | 普通三方应用无公开短信读取能力 | 原生 HAP 只能承担配置、状态等伴随功能 | 不宣称支持自动短信转发 |

HarmonyOS NEXT 若要完整接入，需要把短信入口迁移到运营商网关、独立蜂窝短信设备，或继续由 Android/鸿蒙 4.x 设备接收。

## 设计

```text
SIM 新短信
  -> Android/鸿蒙 4.x 客户端
  -> 本机加密待发队列
  -> 用户自己的 SMTP 服务
  -> 收件邮箱
```

- 客户端只申请接收新短信所需的最小权限，不读取历史短信。
- SMTP 授权码和待发短信正文使用 Android Keystore 保护。
- 网络中断时保留加密队列并重试。
- 支持 SMTP over TLS（465）和 STARTTLS（587），不允许明文认证。
- 默认建议跳过疑似验证码短信；用户需要明确确认短信外发风险后才能启用。

## 仓库结构

- `clients/android/`：Android 与鸿蒙 2/3/4 兼容客户端。
- `clients/harmony-next/`：仅在存在真实可用能力时添加；不会用通知读取或无障碍模拟冒充短信权限。
- `docs/`：SMTP 配置、真机验证和平台能力说明。

## 当前开发目标

当前功能分支实现纯客户端直连 SMTP，不需要自建或使用第三方中继服务器。首个可交付版本需要同时通过单元测试、Android lint、APK 构建和 Mate 50 Pro 真机短信验证。

## 开发流程

1. 从 `main` 创建功能分支。
2. 在功能分支实现并运行本地测试与构建。
3. 推送分支，由 GitHub Actions 重复验证。
4. 检查通过后再合并；发布签名和服务器部署凭据不进入仓库。

本项目仅用于设备所有者明确授权的短信。部署者负责遵守适用的隐私、通信和数据保护要求。
