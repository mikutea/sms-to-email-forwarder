# 应用内更新交互与覆盖安装审计

审计日期：2026-08-25

目标版本：`1.1.0-beta.1`

测试环境：项目专用 VPS 上的 Android 15（API 35）模拟器

## 结论

应用内更新主链路已跑通：发现版本、App 内下载、进度与取消、资产大小和 SHA-256 校验、包名/版本/签名校验、首次安装来源授权、返回后自动续接系统覆盖安装，以及安装后的数据和权限保留。

普通第三方 App 无法绕过系统最终安装确认；该确认框属于预期安全边界。

## 验证步骤

1. `01-update-dialog.png`：发现新版本后显示更新说明和“下载并更新”，视觉状态健康。
2. `02-download-progress.png`：应用内玻璃态进度框、取消操作和五项校验说明完整，视觉状态健康。
3. 真实 GitHub Release 下载：APK 声明大小和 SHA-256 通过；测试场景尝试旧版本时被递增版本代码校验正确拒绝，安全状态健康。
4. `03-install-permission-dialog.png`：首次安装来源授权前给出原因、范围和返回后续接说明，交互状态健康。
5. `04-system-source-permission.png`：准确进入雁笺单应用“允许来自此来源”页面，系统路由健康。
6. `05-system-update-confirmation.png`：授权返回后自动进入系统“更新此应用”确认框，系统交接健康。
7. 完成覆盖安装：`versionCode 9 → 10`、`versionName 1.0.1-beta.1 → 1.1.0-beta.1`；`firstInstallTime`、应用数据目录 inode 和已授予短信权限保持不变，升级状态健康。

## 安全检查

- 只解析官方仓库、标签和资产名称严格匹配的 APK。
- 只允许 HTTPS，并限制 GitHub 发布资产跳转主机和 100 MB 文件上限。
- 下载完成后检查 SHA-256、包名、版本号、递增 versionCode 和与当前安装版本相同的签名证书。
- APK 仅保存在应用私有缓存，通过不可导出的 FileProvider 向系统安装器临时授予读取权限。
- 任何下载、校验、授权或安装失败都不修改当前版本和本机配置。
