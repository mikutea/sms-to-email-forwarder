# 隐私与安全设计

## 数据流与最小权限

雁笺只申请网络、接收新短信、开机恢复和网络状态权限。它不申请历史短信、通讯录、通话记录、存储、无障碍、通知读取或 Root 权限。

新短信由系统广播交给 App 后先写入本机加密队列，发送任务再通过用户配置的 SMTP 服务器投递。没有项目运营的中继服务器，也没有遥测上传。

## 本机数据

- SMTP 授权码、待发短信发件人/正文和历史记录使用 Android Keystore 支持的 AES-GCM 加密。
- 应用备份和设备迁移提取均关闭。
- 敏感界面启用 `FLAG_SECURE`，阻止普通系统截图和最近任务缩略图。
- 历史最多保留 500 条和 90 天；用户可单独清空历史或待发队列。

配置导出包含 SMTP 主机、用户名、邮箱地址和规则，不包含授权码、短信正文或历史。导入后自动关闭转发和旅行守护，并要求重新填写授权码、隐私确认与后台确认。

## 网络与投递

- 仅支持建连即 TLS 或强制 STARTTLS。
- 始终启用服务器证书主机名校验，不提供跳过校验选项。
- SMTP 调试日志关闭；状态与诊断报告不包含授权码和短信正文。
- SMTP 成功响应只能证明服务器接受了邮件，不能证明最终进入收件箱。

## 威胁边界

短信发件人、其他本地 App、导入文件和 SMTP 服务端均按不可信输入处理。系统短信接收器受 `BROADCAST_SMS` 权限保护；其他后台组件不对外导出。用户正则使用 RE2/J 线性时间引擎；单条短信正文、待发队列行数/密文体积和导入文件均设有上限，后台发送任务按唯一名称合并。

设备已 Root、系统被攻破、攻击者已解锁并控制设备，或恶意键盘读取输入等情形不在普通 App 可防御范围内。真正需要企业级远程可观测和严格一次投递时，应使用受控短信网关，而不是纯手机直连 SMTP。
