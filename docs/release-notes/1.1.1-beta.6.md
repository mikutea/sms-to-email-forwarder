# 雁笺 1.1.1 Beta 6

发布日期：2026-08-29

Beta 6 重点解决“后台显示大量待发”和“成功转发后系统短信仍未读”两类问题。它可以从 Beta 5 直接覆盖安装，正式签名、邮箱配置、规则、权限和本机记录均保持兼容。

## 待发队列修复

- 待发数量按短信、心跳、提醒和其他消息分别显示，不再把所有后台状态邮件都称为短信。
- “立即重试”会清除旧退避等待并马上调度；紧急短信的短退避使用独立唤醒任务，不会排在另一条消息的六小时等待之后。SMTP 测试恢复、App 启动、开机和覆盖升级也会重新核对持久队列。
- 重复心跳自动合并，升级时也会清理旧版已积压的重复心跳；非短信状态消息预留独立上限，不再挤占短信队列容量。
- 每条失败记录显示下一次自动重试时间，便于判断是正在等待还是已经卡住。

## 可选标记系统短信已读

- “设置 → 隐私与安全”新增已读联动，默认关闭，需用户主动授予 Android 通知使用权。
- 只在邮件已被 SMTP 接受后，使用手机本地收到广播的时间匹配默认短信应用通知，并请求 Android 标准“标记已读”动作；记录会明确显示“已请求”，最终状态仍由默认短信应用处理。
- 仅时间接近、多个通知无法唯一判断、短信应用没有标准动作或授权被撤销时都不会执行；已读联动本机记账失败也不会把已被 SMTP 接受的邮件重新发送。
- 为兼容正文脱敏规则，开启功能后只保留原短信最多 16 个规范化字符的 Keystore 加密匹配线索，不为匹配额外保存完整原文；成功后的临时请求从 SMTP 成功起设置 10 分钟有效期。过期项不会再参与匹配，持久清理任务与数据库重开会删除密文。其他应用通知正文不会写入队列、历史或诊断报告。

## 安装后建议

1. 直接覆盖安装，不要卸载旧版，以保留邮箱配置和本机数据。
2. 打开“转发记录”查看按类型拆分后的待发数量；如有积压，点“立即重试”。
3. 如需自动已读，在“隐私与安全”开启功能并完成系统通知使用权确认。
4. 发送一条新的普通短信，确认邮件到达、转发记录显示 SMTP 成功，并检查系统短信会话是否变为已读。

## 验证边界

JVM、Android Lint、构建和 Android 15 / API 35 隔离虚拟设备队列回归均已通过。不同厂商短信 App 不一定提供标准“标记已读”动作；缺少动作时雁笺会明确记录原因并保持短信原状态。真实短信、锁屏和厂商后台策略仍需在实际设备上完成最终闭环。
