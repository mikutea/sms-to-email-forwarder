# 雁笺 1.1.1 Beta 7

发布日期：2026-08-31

Beta 7 修复真机发现的已读联动超时状态问题。它按同一包名与正式签名设计为可从 Beta 6 直接覆盖安装，并应保留邮箱配置、规则、权限、旅行守护状态和本机转发记录；这些 Beta 7 覆盖安装结果仍以签名包真机复验为准。

## 已读请求不再长期等待

- 部分厂商系统会把 WorkManager 延迟到 10 分钟有效期之后，旧版记录可能长期显示“正在请求系统短信标记已读”。
- Beta 7 在 App 回到前台和读取转发历史时主动结算过期请求，立即显示“系统短信未标记已读（未找到可安全调用的系统动作）”。
- 结算过程同时删除临时加密匹配线索；它是幂等操作，与通知匹配、开关变更和历史清理使用同一互斥边界。
- 该修复只更新可选的系统短信状态，不会把已经成功的邮件重新入队，也不会制造重复邮件。

## 真机发现过程

- Beta 6 在 HarmonyOS 4.2 真机上完成了保留数据的覆盖安装，原有 SMTP 配置、短信权限、通知权限和旅行守护状态均保留。
- 锁屏收到新短信后，转发记录显示 SMTP 已接受邮件，待发数量回到 0，应用没有崩溃或后台任务失败。
- 当前默认短信应用没有持续暴露可安全调用的标准“标记已读”动作；邮件发送不受影响，但旧版超时状态没有按时收敛，由此触发本次修复。

## 安装后验证

1. 直接覆盖安装，不要卸载旧版。
2. 打开“设置 → 隐私与安全”，确认通知使用权和已读联动开关仍符合你的选择。
3. 发送一条新的普通短信，确认邮件到达且转发记录待发数量为 0。
4. 如果默认短信应用没有提供标准已读动作，最多等待 10 分钟后重新打开雁笺；记录应明确显示未标记原因，不再长期停在“正在请求”。

## 验证边界

JVM、Android Lint、Debug 构建和 Android 15 / API 35 隔离虚拟设备 37 项回归均已通过。不同厂商短信 App 是否提供标准“标记已读”动作仍由其通知实现决定；Beta 7 不会使用 Root、无障碍自动点击或私有 API 绕过系统边界。签名 Beta 7 仍需覆盖安装到真实设备，复验超时记录收敛和配置保留。
