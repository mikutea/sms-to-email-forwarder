# 雁笺 1.1.1 Beta 8

发布日期：2026-08-31

Beta 8 修正转发记录页“今日成功”的统计口径，并延续 Beta 7 已验证的安全已读边界。它按同一包名与正式签名设计为可从旧版直接覆盖安装，保留邮箱配置、规则、权限、旅行守护状态和本机转发记录。

## “今日成功”现在代表什么

- 旧版实际统计最近加载的 50 条记录，标题却写成“今日成功”；新成功挤出一条旧成功时，数字可能完全不变。
- Beta 8 改为统计手机当前时区从本地日期起点到下一日期起点之间被 SMTP 服务器接受的成功投递。
- 首个 SMTP 通道接受邮件时，接受时间会与已经投递的通道位一起持久化；即使本机成功终态稍后重试并跨过午夜，也不会改写日期。
- 成功数按分钟累计在独立小表中，不再依赖最多保留 600 条的详细历史；当天成功量超过历史容量时也不会封顶、减少或回到滚动窗口语义。
- 前后日期边界分别计算，而不是在已经被夏令时归一化的起点上直接加一天，因此旅行切换时区、23/25 小时日以及午夜跳变地区都按手机显示的日期统计。
- 后续已读联动成功、失败或超时只更新说明，不会把成功投递移动到另一天。
- 升级前的成功记录没有独立成功时间，迁移时会使用旧记录最后可用的状态时间作一次兼容回填；升级后的投递使用精确成功时间。

## 系统短信已读边界

Beta 7 真机复验已确认：锁屏新短信能够进入加密队列、由 SMTP 成功投递并把待发数量恢复为 0；当默认短信应用没有提供语义明确且可安全调用的标准“标记已读”动作时，雁笺会明确显示“系统短信未标记已读”，不会让状态一直停在请求中。

这意味着邮件转发成功不等于系统短信一定变为已读。Beta 8 不会申请默认短信应用身份，也不会使用 Root、无障碍模拟点击或私有接口；这些做法会显著扩大短信与设备控制权限，并不适合本项目的安全目标。

## 覆盖安装后检查

1. 直接覆盖安装，不要卸载旧版。
2. 打开转发记录，确认原有记录与邮箱配置仍在。
3. 发送一条新的普通短信，确认邮件到达且待发数量回到 0。
4. 回到转发记录，确认“今日成功”增加，并且不会因已读联动后续结算而改变日期归属。

## 验证边界

本次版本加入本地自然日、普通及午夜夏令时边界、首次 SMTP 接受时间持久化、终态事务回滚、历史容量裁剪与后续详情更新隔离的自动化回归。修复审查意见后的最终测试数量与结果将在发布前重新同步。

虚拟设备不能证明真实短信广播、厂商后台策略或系统短信应用动作。签名 Beta 8 的覆盖安装、数据库迁移、配置保留和新成功统计仍以发布后的实际设备复验为准。
