# SMTP 配置与安全

## 用户需要准备的信息

- SMTP 主机名；
- 端口；
- `SSL/TLS`（通常为 465）或 `STARTTLS`（通常为 587）；
- SMTP 用户名；
- 邮箱服务生成的授权码或应用专用密码；
- 发件邮箱和收件邮箱。

具体主机、端口和授权码开启方式应以邮箱服务商当前官方说明为准。不要把网页登录密码填进 App。

选择 `SSL/TLS` 时端口会默认联动为 465，选择 `STARTTLS` 时默认联动为 587；若服务商明确提供其他端口，仍可手动修改。飞书邮箱还需要管理员允许第三方邮件客户端，并使用服务端生成的专用密码。

## 本机保护

- SMTP 授权码使用 Android Keystore 的 AES-GCM 密钥加密后保存。
- 待发送短信的发件人和正文也使用同一设备内密钥加密。
- 应用关闭系统备份，防止配置和队列进入普通应用备份。
- 配置页启用 `FLAG_SECURE`，避免系统截图和最近任务缩略图记录授权码。
- 日志和状态栏不记录 SMTP 授权码或短信正文。

## 传输要求

App 只允许以下两种 SMTP 模式：

- 建连即启用 TLS；
- 建连后强制升级为 STARTTLS。

两种模式都启用服务器证书主机名校验。项目不提供关闭证书校验或明文 SMTP 的选项。

## 邮件格式

每次投递使用标准 `multipart/alternative`：支持 HTML 的邮箱客户端优先显示移动端友好的结构化卡片，不支持 HTML 的客户端显示等价纯文本。短信邮件包含发送方、接收时间、SIM、正文和短投递编号；SMTP 自检、旅行守护心跳和设备提醒使用各自独立主题。

发送方、正文和投递编号均按不可信输入处理：HTML 视图会转义特殊字符，主题会移除回车换行并限制长度。邮件不加载远程图片、脚本或雁笺服务器资源。

## 投递语义

每条短信拥有由 Android Keystore HMAC 密钥生成的稳定本机消息 ID，并映射到稳定的邮件 `Message-ID`。邮件中只展示缩短后的投递编号，便于排查重复投递；成功响应后，App 删除本机队列中的正文。

如果 SMTP 服务器已经接收邮件，但手机在收到成功响应前断网，App 无法判断远端最终状态，后续重试可能产生重复邮件。这是直连 SMTP 的固有边界，不能宣称严格 exactly-once。
